During Phase 2 of my multi-tenant SaaS platform, I introduced environment separation (dev, stage, prod), reusable Terraform modules, and a production-style CI pipeline with matrix validation, linting, and security scanning, and I faced multiple cascading failures while stabilizing it. Initially, Terraform validation failed due to inconsistent variable declarations across environments, where the provider referenced var.env but the variable wasn’t declared consistently, so I standardized variable naming and ensured each environment root defined required inputs properly. I also resolved duplicate Terraform block issues by consolidating required_version and provider configuration into a single root block to avoid structural conflicts. When I added TFLint, the CI began failing because I used tflint --recursive, which scanned scaffolding folders like globals/ and incomplete modules, triggering false positives such as module structure errors, unused declarations, and required version warnings; instead of disabling linting entirely, I scoped lint execution only to real environment roots and reusable modules using --chdir, which eliminated noise while preserving meaningful validation. I encountered plugin configuration errors due to missing version pins in the Terraform ruleset plugin, so I explicitly pinned plugin versions to prevent unpredictable upstream breakages. During scaffolding, many modules were partially wired, causing additional lint noise for unused variables and undocumented inputs, so I selectively disabled only scaffolding-related rules while keeping structural safety checks like terraform_required_providers enabled, maintaining signal over noise rather than weakening standards. I also fixed YAML indentation and workflow structure issues that caused GitHub Actions parsing failures by separating validation and lint/security jobs clearly. Finally, tfsec failed with GitHub API rate-limit errors even after setting an environment variable, and by inspecting container logs I discovered the action expected INPUT_GITHUB_TOKEN via the with.github_token parameter rather than an env variable, so I passed the token correctly and pinned the tfsec version to avoid future instability. The final result was a fully stable, matrix-based Terraform CI pipeline with strict formatting enforcement, scoped linting, pinned tool versions, and authenticated security scanning — demonstrating disciplined infrastructure engineering, debugging under pressure, and production-grade CI design rather than simply writing a workflow file.
